# 2026-11-09

## 项目现状诊断（能否运行 / 架构思路评审）

- 验证结果：Go 1.26.4 `go build ./...`、`go test ./...` 全绿；前端 `npm run build` 通过、vite dev 与 API `/healthz` 均 200，无 token 业务接口 401；新实例 AutoMigrate 出 9 张表。默认配置是 SQLite + 本地文件存储 + 无 Redis，因此 Mac 上零外部依赖就能跑控制台。本机 Docker daemon、MySQL/Redis/MinIO 均未运行。
- 运行边界：macOS 无 binderfs，跑不了 Redroid；真机链路（容器启动 → apply-profile readback → 画面/注入）从未在 arm64 Linux 上端到端验证，`deploy/android-image` 脚本仅语法检查、NDK 未编译。这是全项目最大风险：控制面超前、数据面落后、运行时未验证。
- 做对的部分：分层（控制面不碰 Docker、agent 拉任务、DB 为真相源、Redis/MinIO 可选降级）；群控（比例坐标按设备重编码、32 深度串行控制队列、15s TTL 控制锁、同档案分组、批量任务事务展开、脚本任务显式拒绝）；License 边界（Damru 非商用、scrcpy Apache、ws-scrcpy MIT）。
- 仍是原型的部分：每实例一个 python stream 进程、PNG 全速推、`adb shell input` 200–500ms、帧与控制共用一条 WS（队头阻塞未解）、前端 3 秒轮询 + `<img src=data:>` 换帧；ADR 0003 的 H.264/WebCodecs/订阅分级帧率仍为 Proposed，设备墙页面未实现。
- 文档/代码冲突：ADR 0002 声明「不 patch GLES、不装 syscall hooks」，但 `deploy/android-image` 有 LD_PRELOAD hook 且 prod profile 默认开启；README 把「复用已有 MySQL/Redis/MinIO 容器」写成前提，与实际默认降级路径不一致。真机化/抗检测一支投入最重、验证最少、合规风险最高，建议收敛定位并统一边界。
- 工程化：git 只有 1 个 commit、几乎全部源码 untracked；`.gitignore` 仅 5 行（`__pycache__`/`.DS_Store` 未忽略）；go.mod 依赖全部标 `// indirect`；JWT secret 有开发默认值、WS `CheckOrigin` 恒 true、token 走 query string。
- 项目自带 `data/xphone.db` 是 10-08 旧库，缺 `control_group`/`batch_task` 两表；用当前代码启动会由 AutoMigrate 自动补齐（已在临时库验证）。
- 本次验证用 `/tmp/xphone-smoke/data` 作数据目录，未污染项目数据；临时 API 与 vite 进程已清理，端口 18110/18111 已释放。
