# 2026-10-10

## deploy/android-image：构建机选型（Mac vs Linux）澄清 + 脚本增强

用户问「编译镜像在 Mac 还是 Linux、需要什么条件」。结论（已写进 README 6.0）：

- 三件事分开：**NDK 交叉编译 .so** 在 Mac 做最合适（不需要 Docker/内核；NDK macOS 版 host tag
  恒为 `darwin-x86_64`，Apple Silicon 靠 Rosetta 2 跑，`softwareupdate --install-rosetta`）。
- **docker build**：Mac 可以做。Dockerfile 用 `SHELL ["/system/bin/sh","-c"]`，所有 RUN 在
  Android rootfs 内执行 → 构建机 CPU 架构必须与目标镜像一致。Apple Silicon Mac 构建 arm64
  原生可行；Intel Mac 构建 arm64 需 QEMU 模拟 bionic，失败率高，不推荐。
- **docker run**：Mac 绝对不行 —— Docker Desktop 的 linuxkit VM 内核无法加载 binder_linux/ashmem，
  `/dev/binder` 不存在。必须原生 Linux（物理机/裸金属/KVM VPS，能 modprobe）。
- 构建机不需要任何内核模块，只要 Docker 20.10+ (BuildKit) + ~8GB 磁盘。

### 改动
- `scripts/build.sh`：新增 `PLATFORM` 环境变量 → `--platform`；打印构建机架构并对跨架构（x86→arm64）
  与 x86+arm 基础镜像组合给出警告。
- `native/xphone-fake/build-ndk.sh`：Apple Silicon 上检测 Rosetta（pgrep oahd），未装则提示安装命令。
- `README.md`：新增「6.1 在哪台机器上构建」对比表 + 推荐工作流（Mac 编 .so/改配置 → arm64 服务器
  build+run；或 `docker save | ssh docker load`），并强调改 config/ 无需重建镜像，restart 即可。

## 追加：dev / prod 环境分层（用户纠正：Linux 才是生产，Mac 只做测试）

设计：`XPHONE_ENV=dev|prod` 一个变量切两种运行形态，配置按
`config/device.env`（基线）→ `config/profiles/<env>.env`（覆盖）两段加载，容器内外顺序一致。

- 新增 `config/profiles/dev.env`（STEALTH=0 / ROOT_MODE=adb / SELINUX=permissive / GPU guest /
  720×1280@15 / XFAKE_DEBUG=1）与 `prod.env`（STEALTH=1 / magisk / enforcing / GPU auto /
  1080×2400@30 / STEALTH_PRELOAD=1）。
- 新增 compose 覆盖层：`docker-compose.dev.yml`（1CPU/2G/unless-stopped）、
  `docker-compose.prod.yml`（2CPU/4G/always）、`docker-compose.gpu.yml`（/dev/dri 直通）。
- 新增 `scripts/up.sh <dev|prod> [--gpu] [透传参数]`：写 .env 的 XPHONE_ENV/DATA_DIR →
  预检（prod 强制 Linux + binder + arm64，不满足直接退出；x86 只告警）→ 组合 compose 文件 → up -d。
- `entrypoint.sh` 加载 profiles；`build.sh --env dev|prod`（dev 镜像 tag 加 -dev 后缀）；
  verify/stealth-audit/test-preload 三个宿主脚本同步加载 profile，否则期望值与容器内不一致。
- verify.sh 的 root 校验按 ROOT_MODE 分三种：adb 直接查 uid、magisk 查 `su -c id -u`、none 反查。
- 关键澄清（与用户原认知不同）：**Mac 上跑不了容器**（Docker Desktop 的 linuxkit 内核无 binder），
  Mac 只能做 NDK 编译 + 编辑配置 + docker build；dev 测试实例同样要跑在 Linux 上。
